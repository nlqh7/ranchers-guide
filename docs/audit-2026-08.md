## Manual Decision

The site does not have a domain-wide thin-content problem. Its core guides, databases, map, bilingual answer pages, and working tools have useful standalone intent. A broad sitemap purge or homepage redesign would remove valid discovery paths without addressing the real risks.

The automated grades are triage labels, not publication decisions:

| Class | Routes or groups | Decision |
| --- | --- | --- |
| A | Homepages, maps, substantial guides, and animal/crop/material databases | Keep indexed and improve only from verified demand or new evidence. |
| B | Database/problem hubs, short problem answers, community snapshot, smaller tools | Keep when they solve a distinct task; strengthen clusters and next steps over time. |
| C | About, contact, privacy, methodology, research, and the bilingual Chicken Troubleshooter | Keep trust pages accessible. The troubleshooter is graded on short static text by this audit but remains indexable because its six evidence-linked interactive flows solve a distinct task; use interaction tests rather than filler text to judge it. |
| D | 404, contribution workflow, English and Chinese search shells | Keep outside the sitemap and `noindex`; they are functional routes, not search landing pages. |

## P0 - Approval and Trust

1. Keep `/404`, `/contribute`, `/search`, and `/zh/search` outside the sitemap and explicitly `noindex`.
2. Correct stale rows on `/research` when an official patch changes a previously open issue. The queue must ask only for residual reproductions on the current build.
3. Run one aggregate quality command that covers generated-page drift, structured-data checks, navigation, search, maps, version semantics, and internal links.
4. Do not add low-evidence database pages simply to increase page count.

## P1 - Retention

1. Upgrade the existing map search instead of creating a second map finder: aliases, query-string deep links, and a complete path from a result to a pin, region, directory row, or answer page.
2. Build one bilingual chicken troubleshooting tool from a shared evidence source. It should produce an ordered checklist, not diagnose an unverified cause.
3. Preserve source links and build labels in every interactive result.

## P2 - Evidence-Gated Expansion

1. Publish a crop calendar only after current-build tests establish planting-day counting, growth completion, regrow timing, and season-boundary behavior.
2. Let search demand choose the next structured dataset. The evidence-gated materials database is now live; quest prerequisites currently outrank a generic item catalog.
3. Refresh dated community snapshots as dated editions; do not silently rewrite old observations as current facts.

## Change-Control Rule

Homepage layout and broad navigation are frozen unless analytics or usability testing identifies a concrete failure. Content facts, patch status, and search/map behavior remain eligible for continuous maintenance.
